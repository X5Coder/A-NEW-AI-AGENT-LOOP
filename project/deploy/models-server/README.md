# سيرفر النماذج — أمر واحد وخلاص 🚀

> **أمر واحد على أي نظام (يفحص OS تلقائياً):**
> ```bash
> cd project/deploy/models-server
> python install.py                 # تفاعلي كامل (Windows / Linux / macOS)
> ```
> على Linux/macOS يوجد غلاف رفيع `./install`، وعلى Windows ‏`install.cmd` —
> كلاهما ينادي `install.py` نفسه. `./install.sh` ما زال يعمل مباشرةً (نفس التدفق).

```bash
python install.py --check           # فحص OS + البيئة فقط بدون أي تغيير
python install.py --yes             # بدون أسئلة (كل الناقص تلقائياً + بيانات الواجهة من البيئة)
python install.py --cpu             # تجاهل كرت الشاشة (CPU فقط)
python install.py --port 9000       # منفذ مخصص (يُحفَظ ويُعاد استخدامه)
python install.py --force-recreate  # إعادة إنشاء الحاوية (عند تغيّر المنافذ)
```

> **غير التفاعلي (`--yes` أو بدون طرفية):** الإيميل والباسورد لا يُسأل عنهما —
> صدّرهما في نفس سطر الأمر (مرة واحدة، ولا يُحفَظان كنص في أي ملف):
> ```bash
> UI_EMAIL_PRESET=you@gmail.com UI_PASSWORD_PRESET='باسورد-قوي' ./install.sh --yes
> ```
> بدونهما يتوقف **مبكراً قبل أي تنزيل** برسالة واضحة (لا تنزيل 20GB ثم فشل).

## التدفق بالترتيب (اللي بيحصل بعد ما تكتب الأمر)

1. **كل الفحوصات أولاً:** Docker (+تثبيت تلقائي على Linux) · Python والمكتبات ·
   **CPU/GPU** (+ نسخة CUDA وقناة torch المناسبة لها) · **RAM + VRAM** · **المساحة
   المتاحة** · و**حالة المشروع** (توكن/إعدادات موجودة؟ صورة Docker مبنية؟
   و**جدول بكل نموذج**: الاسم + الحجم + الحالة).
2. **الاختيار:** تُعرض النماذج الأربعة بالاسم + **الحجم الفعلي** + الحالة، وتعلّم
   عليها بالأسهم و`Space` ثم `Enter` (`a` للكل). المعلّم افتراضياً = كل غير المكتمل.
   **لو ألغيت ورجعت تاني: يعرض الجدول من الأول وتختار من جديد.**
3. **فحص دقيق للاختيار:** المطلوب = المختار غير المكتمل **+ 5 جيجا ثابتة**؛ لو المساحة
   ناقصة يتوقف قبل أي تنزيل. وتحذير ذاكرة بأرقام (يكمل بموافقتك).
4. **حجز المساحة على الإجمالي:** **ملف حجز واحد** بحجم إجمالي التنزيل (مش ملف لكل
   نموذج)، يُحرَّر تدريجياً مع كل نموذج يبدأ تنزيله.
5. **التنزيل:** كل نموذج **لوحده** مع **بروجريس بار حقيقي** (يتابع الحجم الفعلي على
   القرص). لو النموذج ناقص/جزئي → **يكمل عليه**. لو ألغيت `Ctrl+C` وأعدت الأمر →
   **يعرض الجدول من الأول وتختار تاني، والناقص يكمل من حيث توقف**.
6. **المدقّق تلقائياً:** `scripts/doctor.py` يفحص المشروع كله ويقول الناقص والكامل.
7. **البناء بقناة torch الصحيحة → فحص GPU الحقيقي → التشغيل:** تُبنى الصورة
   (`cu126/cu124/cu121` حسب التعريف أو `cpu`)، ثم يُسأل `torch.cuda` داخلها
   فعلاً — GPU حقيقية فقط تُفعَّل (بأقصى سرعة: `fp16` للرؤية و`bf16` للصوت
   تلقائياً). **تُحمَّل النماذج المختارة فقط** في هذا التشغيل.
8. **تأمين الواجهة أثناء الإعداد:** يطلب **إيميل Gmail فقط** ثم **باسورد الواجهة**،
   ويحفظهم في `.env`، فتدخل الواجهة بيهم **مباشرةً** — كل دخول يمنح جلسة جديدة
   تنتهي بعد 30 يوماً، والخروج يُبطلها فوراً.
9. **النهاية:** رابط الواجهة (بدون توكن — مربوط بالإيميل والباسورد) + توكن النماذج
   للأيجنت + `/health`.

## أمر `doctor` 🩺

أمر منفصل يعرض **حالة كل حاجة** (بيئة + نماذج)، ومنه تختار النموذج **غير المحمّل أو
غير المكتمل وتحمّله كامل**:

```bash
./doctor.sh           # حالة كاملة + اختيار + تنزيل
./doctor.sh --check   # حالة فقط بدون تنزيل
```

## الأمان (مهم)

| الرابط | الحماية |
|---|---|
| `/` الواجهة | **إيميل Gmail + باسورد الواجهة** (جلسة جديدة كل دخول، تنتهي بعد 30 يوماً، الخروج يُبطلها فوراً، حد 5 محاولات فاشلة/دقيقة لكل IP) — الرابط بدون توكن، مربوط بيهم |
| `/embed` `/vision` `/asr` `/tts` | **توكن سري `API_TOKEN`** (الأفضل `Authorization: Bearer` — يقبَل `?token=` للتوافق) |
| `/health` | عام عمداً (فحص docker بدون أسرار — حالة التحميل فقط) |

- الإيميل **Gmail فقط** (`@gmail.com`)، والباسورد لا يُخزَّن كنص أبداً (`salt` +
  `PBKDF2-SHA256` 200000 دورة)، ولا يُطبع أبداً.
- التوكن يُولَّد **أول مرة فقط** ويُحفظ في `.env` ويُعاد استخدامه دائماً (يستخدمه الأيجنت تلقائياً).
- على VPS يُفضَّل HTTPS.

## رسالة النموذج غير المحمّل

أي أداة/مسار يطلب نموذجاً غير محمّل يرجّع **رسالة إنجليزية ثابتة**:

> No local model is available to run this tool. Please install it by running the doctor command.

## افتراضاتنا

1. **نموذج الـ Vision هو `Qwen/Qwen3.5-4B`** عبر `transformers` الحديث
   (`AutoProcessor` + `AutoModelForMultimodalLM`).
2. **الأحجام وقت التشغيل من Hugging Face مباشرة** — لا حجم ثابت في الكود (المجموع الفعلي
   قد يكون أكبر من التقدير لأننا ننزّل كل ملفات المستودع).
3. **فولدر models واحد فقط** (`project/models`) — Docker والتشغيل المحلي يشتركوا فيه،
   وبعد كل نموذج تُكتب علامة `.download_complete` بنفس صيغة `scripts/setup_models.py`.
4. **حجز ثابت 5 جيجا**: يُضاف على الحساب ويُحجَز في النهاية كملف `.reserve-buffer`.
5. `/health` عام بدون توكن عمداً؛ باقي المسارات محميّة.

## المسارات

| المسار | الاستخدام |
|---|---|
| `GET /` | الواجهة (إيميل + باسورد) — حالة النماذج **المطلوبة في هذا التشغيل** فقط |
| `POST /embed` | `{"texts": [...]}` (حتى 64 نصاً، كل نص حتى 2000 حرف) ← vectors + البعد |
| `POST /vision` | ملف `file` (صورة/فيديو) + `prompt` ← نص |
| `POST /asr` | ملف `file` (صوت) ← نص |
| `POST /tts` | `{"text": "جملة قصيرة"}` ← ملف wav |
| `GET /health` | فحص صحة عام |

## تحديث أو تبديل نموذج

1. عدّل `repo_id` في `models.yaml`.
2. `rm -rf ../../models/<مجلد-النموذج-القديم>` ثم `./install.sh` (علّم الجديد فقط).

## أوامر تفيدك

```bash
./install.sh --yes --port 9000   # بدون أسئلة (يختار كل الناقص تلقائياً + بيانات الواجهة من UI_*_PRESET)
./install.sh --cpu               # تجاهل GPU نهائياً
./install.sh --force-recreate    # إعادة إنشاء الحاوية بعد تغيّر المنفذ/.env
./doctor.sh                      # حالة + تحميل الناقص
docker compose logs -f           # متابعة السجل
docker compose down              # إيقاف (الأوزان تبقى)
docker compose up -d             # تشغيل بدون تنزيل
```
